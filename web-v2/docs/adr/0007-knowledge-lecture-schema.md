# ADR-0007 · 知识讲义契约扩展与向后兼容口径

- 状态：**已采纳（Accepted）** 2026-11-18
- 日期：2026-11-18
- 窗口：S7-E8 / W6（起草）；权威字段以 `web-v2/docs/plans/parallel-contract.md` §1 冻结文本为准，本 ADR 不改动契约，只记录决策与理由
- 相关：`13` §5 I-1/I-4、§8、附录 C；`14` §0（P-1/P-2）；`00` §9；C-1～C-5、W6-1

---

## 背景

V1 的「知识」模块只有 `items`（一句话要点）与 `pitfalls`，`knowledge.json` 共 7 篇约 12KB（`13` §2.3 D-02）。I-1 / I-4 要把讲义升级成"可精读、可看视频、可去练本节"的内容，需要在 `KnowledgeModule` 上加字段，同时改变两件事：

1. `items` 从过去的"必填且非空"放宽为"缺省空数组"，让"只有正文、没有要点"的新讲义能存在；
2. `parseBankJson` 过去对 `knowledge` 只做数组判断后直接断言，现在要走同一套校验、拒绝脏数据（D-05 / I-4）。

这里有一个绕不开的问题：**契约变了，旧数据怎么办？** 旧讲义（含 S1 迁移产物、第二学科题库）散落在用户本地快照与题库包里，无法集中升级。任何要求"必须补字段"或"必须迁数据"的设计，都会让老用户导入失败。

本 ADR 记录的核心决策就是回答这个问题，并顺带定下外链视频的边界。

## 决策

### 1. 六个新增字段全部可选，`items` 放宽为缺省空数组

在 `KnowledgeModuleSchema` 上新增六个字段，全部带默认值或可选：

| 字段 | 类型 | 缺省行为 |
| --- | --- | --- |
| `goals` | `string[]` | `.default([])` |
| `sections` | `KnowledgeSection[]` | `.default([])` |
| `videos` | `KnowledgeVideo[]` | `.default([])` |
| `resources` | `KnowledgeResource[]` | `.default([])` |
| `estimatedMinutes` | `number`（正整数） | `.optional()`，缺省不写 |
| `examFocus` | `string` | `.optional()`，缺省不写 |

`items` 由 `min(1)` 放宽为 `.default([])`，`pitfalls` 继续 `.default([])` 保留兼容。

**关键**：缺省由 `.default([])` 补成空数组，而不是 `undefined`。这样消费方永远拿到数组，不需要到处判空；`estimatedMinutes` / `examFocus` 才是真正"没有就是没有"的缺省。

### 2. 用语义校验守住被放宽的口子

形状层放宽不等于内容可以空。`validateKnowledgeModules` 增加一条可定位的语义约束：

> `items` 与 `sections` 不得同时为空；否则报 `[SCHEMA_INVALID]` / `path = knowledge[i]`。

即：允许"只有要点"（旧形态）、允许"只有正文"（新形态）、不允许"两者皆空"（空壳讲义）。错误码格式沿用契约 §3，定位到具体篇目 `knowledge[i]`，不是笼统的一句"讲义不合法"。

### 3. 旧数据零迁移

**决定：不写任何迁移器，不升 `schemaVersion`。**

判据是一条：**新契约必须是旧数据的超集**。逐项核对：

| 旧数据形态 | 新契约下是否合法 | 原因 |
| --- | --- | --- |
| 只有 `items` + `pitfalls`（当前 7 篇旧讲义） | ✅ 合法 | `items` 非空，满足语义约束；新字段由 `.default([])` 补齐 |
| 只有 `items`，无 `pitfalls` | ✅ 合法 | `pitfalls` 有默认值 |
| S1 迁移产物、第二学科题库的讲义 | ✅ 合法 | 同上，缺字段一律补默认值 |
| `items` 为空（历史空讲义） | ❌ 被拒 | 但这类数据在旧口径下本就是 `min(1)` 拒收的，不存在于合法旧数据中 |

因此**不存在"旧数据读不出来"的情形**，迁移器没有服务对象。

### 4. `schemaVersion` 保持 1，不升版

契约 `SCHEMA_VERSION = 1`（`packages/core/src/schema.ts`），`LearningSnapshotSchema.schemaVersion` 为必须参与校验的版本号。为什么不升到 2：

> 上游依据：W1 窗口对字段清单评估后的建议是「字段全可选、旧数据零迁移则不升版」，`13` §8 变更登记同此建议。本 ADR 采纳该建议并给出完整理由。

- `schemaVersion` 升版的代价是强制所有旧包/旧快照要么被拒（`snapshot.ts` 对高于当前版本的文件直接返回 `SCHEMA_VERSION_UNSUPPORTED`），要么必须写迁移器。
- 本次变更**不破坏任何旧数据的可读性**（见上节），升版换不来兼容性收益，只会给老用户制造一道无谓的导入墙。
- 快照里 `examRecords` 那次字段追加（`00` §9 / 2026-11-17）已经确立先例：**纯追加可选字段不升版**，由 Zod 默认值补齐。本次沿用同一先例。

**例外留痕**：本次真正改变的不是数据形状，而是**导入失败口径**——`parseBankJson` 从"静默收下"变为"形状错就拒绝"。这属于行为变更，单独在 `00` §9 登记，并以 C-3「解析失败一个字节都不写」单测守住，不通过升版来表达。

> 何时应升版：若将来新增**必填**字段、改变既有字段类型、或需要把旧值改写成新值（例如 `pits` → `pitfalls` 若做成破坏性重命名），届时 `schemaVersion` 必须升并配迁移器。本 ADR 只覆盖当前"全可选 + 零迁移"的情形。

### 5. 外链视频：文字自足、可选、点击才加载

讲义视频是新的外部依赖面（R-B），边界如下：

1. **文字自足**：讲义正文（含代码、表格、公式）独立于视频完整可读；断网时视频区显示"需联网"提示而不是黑框或异常（A-5 / B-4）。
2. **可选**：`videos` 缺省空数组；没有视频的讲义照样合法。
3. **点击才加载**：B 站 / YouTube 等站外 iframe 在用户点击前**零第三方请求**，另给 `watchUrl` 跳转；直链 mp4 走原生 `<video>`，相对路径视为随包本地文件、不算联网（B-3、契约 §2 UI 纪律）。
4. **安全**：解析在 `packages/core` 纯函数完成，`javascript:` / `data:` / `vbscript:` 判非法并给可读原因；UI 不把字符串直接拼进 `src`（R-C / B-2 / B-7）。
5. **巡检责任**：外链可能下架或失效，内容侧承担**季度巡检**；失效降级为跳转卡并给提示，不删除文字讲义。BV 号来自公开资料交叉引用、未经实际播放验证，讲义中须标注"合集链接、请跳到对应章节"，不写成"精确到某集的确定链接"（`13` 附录 B）。

## 备选方案与不选的理由

| 方案 | 为什么不选 |
| --- | --- |
| 新字段设为必填，强制旧数据补齐 | 旧快照/题库包无法集中升级，等于让老用户导入失败；与"数据零静默丢失"成功标准冲突 |
| 升 `schemaVersion` 到 2 + 写迁移器 | 旧数据本就可读，迁移器无服务对象；升版只会触发无谓的版本不支持拒绝 |
| `items` 继续必填非空 | 新讲义以正文为主体、可以没有要点列表，放宽才能让 I-1 的八段结构落地 |
| 放宽 `items` 但不加语义校验 | 会出现"既无要点又无正文"的空壳讲义，用户点进去什么都没有；语义约束把口子堵在 `knowledge[i]` |
| 视频自动内嵌 / 预加载 | 违反"未点击零第三方请求"与断网可用；第三方 Cookie 与注入面也不可控 |
| 视频文件随题库包分发 | 体积膨胀，与小程序分包约束和"运行时零第三方依赖"取向冲突（13 §3.2） |

## 后果

**好处**

- 旧数据零迁移即可读，向后兼容可证明（C-1）；新字段写错当场被拒并定位（C-2）。
- 消费方拿到的是数组而非 `undefined`，渲染层无需到处判空。
- 不升版意味着不制造新的版本墙，`schemaVersion` 保留给真正破坏性的变更。
- 视频作为可选增强，断网与无视频场景都不降级文字讲义。

**代价 / 约束**

- `items` 与 `sections` 的语义约束无法在 Zod 形状层表达，只能放在 `validateKnowledgeModules` 里——必须由单测守住，不能靠"类型系统保证"。
- `parseBankJson` 的失败口径变化（静默收 → 拒绝）是破坏性**行为**变更，已单独在 `00` §9 登记；旧版可能容忍的畸形讲义在新版会被挡，需在导入提示里给出可定位原因。
- 外链视频引入长期维护成本（季度巡检），是接受"不托管视频"换来的取舍。

## 强制执行（验收映射）

1. C-1：旧形态讲义（仅 `items`）解析通过，新字段补默认空数组——契约单测证明。
2. C-2：空讲义（既无 `items` 又无 `sections`）被拒且给出 `knowledge[i]` 路径。
3. C-3：含非法视频字段的题库包导入被拒，且不写入任何数据。
4. C-4：导出 → 再导入恒等，讲义篇数与小节数不变。
5. W6-2：`README.md` §2 给出可从 Markdown 重建 `knowledge.json` 的命令，并能实际跑通 `pnpm knowledge:build`。
6. 任何新增必填字段、字段类型改变或破坏性重命名，必须先开新 ADR 并升 `schemaVersion`；本 ADR 的"不升版"结论仅对当前全可选变更有效。
