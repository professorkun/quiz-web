## 1. 阶段目标

**目标陈述**：把 S2 的练习切片装进完整的信息架构，接上本地持久化，让"不用登录就能持续刷题"成立；并用一个**第二学科的极小题库**证明"通用"是真的——换题库不需要改代码。

**可衡量目标**

| 编号 | 指标 | 目标值 | 验证方式 |
| --- | --- | --- | --- |
| G3-1 | 页面完整度 | 5 个主入口（学习 / 题库 / 刷题 / 复习 / 我的）可进入且各有实质内容 | 逐页走查 |
| G3-2 | 游客可用 | 清空存储后无需登录完成练习并保留记录 | 端到端手测 |
| G3-3 | 记录隔离 | 两库切换后错题/进度/收藏不串 | 双库交叉用例 |
| G3-4 | 持久化 | 刷新/关闭浏览器后游客数据完整恢复 | 手测 + 自动化 |
| G3-5 | 导入导出闭环 | 导出 → 再导入，字段与记录无差异 | diff 对账 |
| G3-6 | 通用性证明 | 第二学科题库**零代码改动**即可使用 | 只用导入功能接入并跑通 |

---

## 2. 范围边界

**本阶段做**

- 五个主入口页面壳与路由
- 题库切换、主题/章节树、标签、难度、状态筛选、题干搜索
- `StorageAdapter` 接口 + Web 端 Dexie/IndexedDB 实现
- 游客练习、错题、收藏、设置的本地持久化
- 标准 JSON 导入导出（题库包 + 学习记录），错误报告
- 一个极小演示题库（第二学科），仅用于验证通用性
- 数据备份入口雏形（导出入口先可用）

**本阶段不做**

- 不做错题状态机与复习调度（S4）
- 不做统计看板（S4）
- 不做模考（S5）
- 不接云、不做登录（S6）
- 不做可视化题目编辑器（S7）
- 不追求视觉效果打磨（S6 前做可访问性与移动端检查）

## 6. 验收标准

### A. 功能

- [ ] 五个主入口均可进入，空状态（新用户）有明确引导，不是白屏
- [ ] 题库切换后当前题库有明确标识，切换后回到该库的进度
- [ ] 主题树、标签、难度、状态筛选可组合使用，结果与数据一致
- [ ] 题干搜索返回匹配题目，无匹配时给出提示
- [ ] 练习设置（范围 / 模式）可保存并在下次进入时恢复

### B. 本地记录

- [ ] 游客无需登录即可练习、产生错题与收藏
- [ ] 刷新页面、关闭浏览器后重开，练习进度、错题、收藏、设置完整恢复
- [ ] 两个题库的记录完全隔离：在 A 库答错不影响 B 库错题数
- [ ] 存储不可用（隐私模式/配额满）时给出可读提示，不白屏不静默丢数据

### C. 导入导出

- [ ] 导出题库包与学习记录均为标准 JSON，含 `schemaVersion`
- [ ] 导出 → 清空 → 再导入，题目、记录、设置逐项一致（diff 为空）
- [ ] 非法 JSON、缺字段、重复 ID 均被拒绝并指出具体题目与字段
- [ ] 未知字段按既定策略处理（拒绝或明确警告），不静默丢弃

### D. 通用性

- [ ] 第二学科演示题库**仅通过导入/配置**接入，未修改业务源码
- [ ] 演示题库可使用六类题型中的至少 3 种，并正常判分
- [ ] 切换后"知识讲义"随题库变化，不是写死的 JavaWeb 内容

### E. 工程

- [ ] 业务代码不直接 `import Dexie`，只通过适配器访问存储
- [ ] 存储 schema 有版本号与升级函数
- [ ] 单测覆盖：筛选组合、导入校验、跨库隔离

### F. 关键场景（Given / When / Then）

1. **游客闭环**
   Given 一个从未访问过的新浏览器，When 打开应用、选 JavaWeb 题库、答 10 题（含 3 题答错）并收藏 1 题，Then 学习页显示进度，复习页列出 3 道错题与 1 道收藏，全程无登录提示阻断。
2. **记录不串库**
   Given 在 JavaWeb 库中已答错第 12 题，When 切换到演示题库并练习，Then 演示题库错题数为 0，切回 JavaWeb 后第 12 题仍为错题。
3. **导出再导入一致**
   Given 已有 20 条作答与 5 道错题，When 导出 JSON、清空存储、再导入同一文件，Then 记录条数、题目 ID、时间戳与设置项逐项一致。
4. **非法导入定位**
   Given 导入包中第 3 题 `options` 为空数组，When 执行导入，Then 导入被拒绝并提示第 3 题（`questionId`）字段 `options` 非法，且数据库中无部分写入。
5. **存储不可用**
   Given 浏览器处于隐私模式导致 IndexedDB 写入失败，When 答完一题，Then 页面提示"当前无法保存记录"，本题仍可继续作答，不崩溃。

### G. 不可接受的情形

- 记录串库（错题混到另一个题库）
- 游客必须登录才能练习
- 导入"成功"但实际丢了若干题且无提示
- 演示题库接入时改了业务代码（说明契约仍不通用）
- 业务层直接依赖 Dexie API

## 8. 阶段特有风险与应对

| 风险 | 触发信号 | 应对 |
| --- | --- | --- |
| "多题库"只做到换标题 | 演示题库接入仍需改代码 | 视为契约缺陷，回 S1 修，而不是在 S3 加 if |
| 存储接口被 Dexie 特性绑架 | 接口中出现游标/索引概念 | 接口只保留通用能力，查询逻辑放上层 |
| 记录串库 | 错题数随题库切换变化异常 | 所有记录强制带 `bankId`，查询必带库过滤 |
| 导入丢数据 | 导入后题数少于源 | 导入前后数量对账，不一致即失败 |
| 页面壳过度设计 | S3 花大量时间在样式 | 本阶段目标是功能可用，视觉打磨留 S6 |
| 演示题库做成第二个大工程 | 花时间造 100 题 | 上限 20 题，够验证即可 |

## 9. 回退方案

1. 版本回退：回退到 `s2-practice-slice`，应用仍可练习（无持久化），数据仍在浏览器中未损坏。
2. 存储升级失败：`StorageAdapter` 保留上一版本 schema 的只读路径，失败时提示并允许导出后重置。
3. 导入事故：导入前自动生成"导入前快照"（可导出 JSON），出错可回灌。
4. 演示题库：可随时移除，不影响主库。
