## 1. 阶段目标

**目标陈述**：用 S1 的契约，把"选题 → 作答 → 判分 → 看解析 → 下一题"这条最短闭环在新架构里跑通，六类题型全部可作答；并解决旧版最脆弱的一环——**刷新后题序、选项顺序与答案的对应关系**。

**可衡量目标**

| 编号 | 指标 | 目标值 | 验证方式 |
| --- | --- | --- | --- |
| G2-1 | 题型覆盖 | 6/6 题型可作答并判分 | 逐题手测 + 单测 |
| G2-2 | 会话可恢复 | 刷新后题序、选项序、已答状态 100% 一致 | 固定种子回归用例 |
| G2-3 | 判分可测 | 判分器纯函数化，Node 下单测全绿 | Vitest |
| G2-4 | 判分正确性 | 多选不依赖展示顺序；填空不产生已知误判 | 用例集（含误判黑名单） |
| G2-5 | 渲染安全 | 恶意 HTML/公式输入被清洗，无脚本执行 | XSS 注入用例 |
| G2-6 | 无云依赖 | 断网状态下完整可练习 | 断网手测 |

## 2. 范围边界

**本阶段做**

- 六类题型：单选、多选、判断、普通填空、代码填空、简答自评
- 每题"渲染器 + 判分器 + Schema"三段式扩展点（禁止在页面里堆 `if/else`）
- 练习模式：顺序、随机、按筛选范围、只刷未做/未掌握
- 即时反馈、解析展示、上一题 / 下一题
- 稳定 `optionId`、可复现洗牌（随机种子）、会话保存与恢复
- 富内容安全渲染：Markdown + 代码块 + KaTeX + 严格 Sanitize
- 旧版纯逻辑迁移（填空归一化、选项随机）并补测试

**本阶段不做**

- 不做完整页面壳与导航（首页/题库页/复习页/我的页在 S3）
- 不做多题库切换 UI（引擎层支持传入不同题库即可）
- 不做持久化到 Dexie（会话先内存 + 最小本地暂存）
- 不做错题状态机、复习调度、统计（S4）
- 不做模考（S5）
- 不做 PWA、不做云

**六类题型与身份约束（来自方案 §7）**

- `single_choice`、`multiple_choice`、`true_false`、`fill_blank`、`code_blank`、`short_answer`

- 题目修订导致会话不可恢复时，明确提示并保留已完成记录

## 6. 验收标准

### A. 题型与判分

- [ ] 六类题型均能渲染、作答、判分并展示解析
- [ ] 多选判分只看 `optionId` 集合，打乱展示顺序后结果不变
- [ ] 单选/判断在同一题目重复作答时结果稳定
- [ ] 填空归一化规则有明确清单，已知误判黑名单为空（全部规避）
- [ ] 代码填空逐空判分，支持部分给分且能定位到具体空位
- [ ] 简答自评可保存档位，且不覆盖作答原文

### B. 会话与状态

- [ ] 随机练习使用种子，同一种子两次生成题序完全一致
- [ ] 刷新页面后题序、选项顺序、已答状态、当前题位置一致
- [ ] 作答记录中是 `optionId`，不是展示字母
- [ ] 题目 `revision` 变化导致会话无法恢复时，有明确提示且已完成记录不丢

### C. 渲染与安全

- [ ] 题干中的 Markdown、代码块、LaTeX 正确渲染
- [ ] 注入 `<script>`、`onerror=`、`javascript:` 链接的用例均被清洗
- [ ] 渲染组件是唯一入口，业务代码不直接注入 HTML

### D. 工程

- [ ] 判分与选题逻辑全部在 `packages/core`，Node 下单测全绿
- [ ] `apps/web` 中不含判分规则
- [ ] 无云、无网络依赖时功能完整

### E. 关键场景（Given / When / Then）

1. **刷新不错位**
   Given 随机练习已答到第 7 题、第 3 题答错，When 刷新页面继续会话，Then 仍在第 7 题，题序与选项顺序与刷新前完全一致，第 3 题仍显示答错。
2. **多选与顺序无关**
   Given 某多选题正确选项为 `opt_b`、`opt_d`，When 选项展示顺序被调换后作答 `opt_d`+`opt_b`，Then 判为正确。
3. **填空不误判**
   Given 标准答案为"Servlet"，When 输入" servlet "与"Ｓｅｒｖｌｅｔ"，Then 按既定归一化规则判定，且该结果与黑名单记录一致，不出现"应为对却判错"。
4. **内容修订冲突**
   Given 会话中某题在题库里 `revision` 从 1 升到 2，When 恢复会话，Then 提示该题已更新、该题按新版本重新作答，其余题与已完成记录保留。
5. **恶意内容**
   Given 题干中包含 `<img src=x onerror=alert(1)>`，When 页面渲染，Then 脚本不执行，攻击串以纯文本或安全形式呈现。

### F. 不可接受的情形

- 判分写在 React 组件里，`core` 无法独立测试
- 用"展示字母"作为答案存储
- 洗牌不可复现，刷新后答案与选项错配
- 为了让填空"更宽松"而吞掉真实错答，且未记录规则
- 直接使用未经清洗的 HTML 渲染题干

## 8. 阶段特有风险与应对

| 风险 | 触发信号 | 应对 |
| --- | --- | --- |
| 题型扩展仍要改页面 | 加第 3 种题型时改了 5 个文件 | 回到 T2-1，先修扩展点再加题型 |
| 填空规则越改越复杂 | 黑名单不断变长 | 规则清单化 + 用例固化；不接受"再放宽一点"式修补 |
| 代码填空结构丢失 | 空位与代码块对应不上 | 以 S1 的空位 ID 为准，渲染层不得重排结构 |
| 会话格式频繁变动 | 每次改动都导致旧会话失效 | 会话带版本号 + 兼容读取或明确提示 |
| 判分为了通过测试而特判 | 出现针对具体题号的 if | 禁止题号特判，规则必须通用 |

## 9. 回退方案

1. 功能开关：练习引擎入口可整体关闭，回到"题库浏览"状态，不影响已提交数据。
2. 会话回退：会话带 `version`，无法兼容时提示"会话已过期，重新开始"，已完成记录保留。
3. 代码回退：阶段标签 `s2-practice-slice` 前一个提交为已知可用点，可整段回退。
4. 数据回退：本阶段不写云端，回退无远程数据风险。

### 11.1 遗留项（交 S3 / S4 / S9，不夹带进本阶段尾巴）

1. **会话存储仍是 localStorage 单槽**（按 `bankId` 分 key）。S3 接 Dexie 时需做一次迁移或明确清空策略。
2. **「只刷未做 / 未掌握」只有引擎能力**（`selectQuestions` 已支持并有单测），UI 未开放——S2 没有 Progress 数据源，S4 接入学习记录后再放开关。
3. **构建产物 1.69MB（gzip 534KB）**：147 题 JSON + KaTeX 字体 + highlight.js 全量。S9 小程序需按需加载/分包，S6 可考虑路由级拆包。
4. **A/B 账号隔离仍未验证**（沿用 S0 用户决策，S6 前必须补）。
5. **`stemInRenderer` 是 S2 新增的题型元数据**：填空题把输入框嵌进题干，页面不再重复渲染原文。新增题型按 ADR-0004 时需一并声明该字段。
6. **阶段标签与 CI 远端首跑**未完成：本阶段改动只在本地分支 `feat/general-s2-practice`，未推送、未开 PR（协议 §5 由人操作）。

### 11.2 关键实现细节（写给下一个会话，别再踩）

1. **Windows 下 `RichText.tsx` 与 `richText.ts` 会撞车**：不区分大小写，TS 报 TS1149 且 import 被解析到错误模块。渲染管线已改名为 `renderRichText.ts`。
2. **pnpm 12 的构建白名单是 `allowBuilds`**，`onlyBuiltDependencies` 已不生效；根 `package.json` 里的 `pnpm` 字段会被忽略并告警（S1 遗留已清理）。
3. **Zod 判别联合成员不能挂 `superRefine`**（S1 已记录），本题型注册表因此把跨字段校验留在联合层。
4. **代码填空的标记数 ≠ 空位数**：真实数据 89 个定义空位 / 97 处标记，同一 `blankId` 可在同文件出现多次；顺序与代码出现顺序也不总一致（002 的 2-7/2-8、005 的 5-18）。一切以 `q.blanks` 的定义顺序为准。
5. **题干归属要显式声明**：填空题若由页面统一渲染 stem，会把 `{{b1}}` 原样显示出来，再被渲染器渲染一遍。用 `stemInRenderer` 元数据解决，不要用 `if (type === ...)`。
