## 1. 题库数据契约（`data.json`）

### 1.1 顶层

```jsonc
{
  "meta": { "title": "JavaWeb 期末题库", "sub": "选择 62 · 判断 45 · 填空 27 · 简答 8 · 应用 5" },
  "questions": [ /* 147 条，混合题型，判别字段为 type */ ]
}
```

题量基线：**147** ＝ 选择 62 / 判断 45 / 填空 27 / 简答 8 / 应用 5。`meta` 只有展示用字符串，**不含版本号、不含 ID 空间**——S1 必须补 `schemaVersion`。

### 1.2 题型判别联合（5 类，字段即现状）

| type | `TNAME` 中文 | 字段 | 字段说明 |
| --- | --- | --- | --- |
| `choice` | 选择 | `no, stem, options[], answer, analysis, kp` | `options` 元素 `{key:"A", text:"..."}`；`answer` 是**选项字母**（如 `"B"`），不是文本 |
| `judge` | 判断 | `no, stem, answer, analysis, kp` | `answer` 只有两种取值：`√`（25 题）/ `×`（20 题），不是"对/错"文字 |
| `blank` | 填空 | `no, stem, blanks[], answer, hint, analysis, kp` | `stem` 内以 `{{BLANK}}` 占位；`blanks` 是答案数组（1–4 个空）；`answer` 是**展示用字符串，不等于 `blanks` 的连接**：单空时可能带注释（`blanks:["Web"]` / `answer:"Web（万维网）"`），多空时才用 `；` 连接（27 题中 18 题含分号）。迁移取 `blanks` |
| `short` | 简答 | `no, stem, points[], analysis, answer, kp` | `points` 是采分点数组（`①…②…`），`answer` 是 `points` 用换行拼成的整段 |
| `app` | 应用 | `no, stem, code[], blankCode[], answer[], analysis, kp` | `code` 为完整代码块（`{label,lang,text}`）；`blankCode` 为挖空版；`answer` 为 `[空位编号, 答案]` 二元组数组，编号形如 `"5-1"` |

`blank` 与 `app` 的关键差异：`blank` 的空位在**题干**里（`{{BLANK}}`），`app` 的空位在**代码**里（`___(n-m)___`），且 `app` 一个题有多段代码、多份文件。

### 1.3 知识点 `kp`

取值只有 **7 类**：`Web 基础 / JSP / Servlet / Spring / SpringMVC / MyBatis / JDBC`。

生成方式（`build_json.py` `kp_of()`，约 213–243 行）：**关键词打分**，先看题干，打不出再看「题干+答案+解析」，取命中词最多的类别；`app` 题不走打分，按题号硬映射 `{1:JSP, 2:JSP, 3:Servlet, 4:SpringMVC, 5:MyBatis}`。

迁移含义：`kp` 是**推导值，不是人工标注**。S1 的 `knowledge.json` 应当收录这 7 类，且允许日后人工改标（推导会错，只是概率低）。

## 2. 题目身份键 `q_key`

### 2.1 生成规则

`data.json` 里**没有** `q_key` 字段。它是运行时拼出来的，只有一处生成逻辑（`template.html` 756 行 `wrongOf()`，以及 1198/1470 行同构写法）：

```
q_key = q.type + "-" + q.no        // 例：choice-3、app-5、blank-27
```

### 2.2 类型前缀就是 `type` 原值

`choice-*` / `judge-*` / `blank-*` / `short-*` / `app-*`。所以 `q_key.split("-")[0]` 可直接还原题型（1198 行 `q_type:k.split("-")[0]` 就是这么用的）。

### 2.3 稳定性风险（S1 必须处理）

`no` 是**题库解析顺序号**（`build_json.py` 里按 Markdown 出现顺序编号），一旦题干增删或换题，`no` 会整体位移 → **同一条旧记录会指向另一道题**。

所以：

- 不得把 `q_key` 当作长期主键
- 新契约须用语义 ID 或 UUID 作主键，旧 `q_key` 存入 `legacyKeys[]`（对应 `02-S1` T1-2）
- 迁移前必须锁定题库文本哈希，否则映射会在下一次题库改动后静默失效

### 3.2 三个 RPC（写操作都走服务端函数，不在客户端拼表）

| RPC | 入参 | 用途 |
| --- | --- | --- |
| `record_wrong_questions` | `{ p_items: [...] }` | 批量写入/累加错题（`wrong_count` 自增在服务端） |
| `save_drill_progress` | `{ p: {kp,q_type,keys,idx,res,total} }` | 覆盖保存「继续刷」进度 |

### 3.3 隔离方式

- 客户端**不传** `owner_id`，由服务端按会话写入 → 说明表上有 RLS，但**具体策略未验证**（§8）
- `wrong_questions` 与 `quiz_mastery` 都靠 `(owner_id, q_key)` 唯一，重复写是幂等的

## 6. 迁移映射表（初版，供 S1 直接落实）

| 旧 | 新契约 | 转换规则 | 风险 |
| --- | --- | --- | --- |
| `data.json.questions[]` | `packages/content/javaweb-final/questions.json` | 按 `type` 拆判别联合，`no` 转为 `legacyKeys:["<type>-<no>"]`，新主键另生成 | 题库改版即失效 → 锁文本哈希 |
| `choice.answer`（字母） | 选项 ID 引用 | 字母 → 该选项 `text` 的稳定 ID；旧数据无选项 ID，需按文本反查 | 同一题选项文本重复时反查有歧义 |

| `short.points[]` | `rubric[]`（采分点） | 逐条转对象 `{text, score}`，旧无分值 → 需按总分配均 | 分值缺失，人工确认一次 |
| `app.code[]` + `blankCode[]` + `answer[]` | `code_blank`（多文件） | 一个 `app` 题 → 多个文件块；`answer` 的 `"5-1"` 编号映射到「文件序号-空位序号」 | 同一空位编号在多文件重复（已知 89 唯一 / 97 字面） |
| `kp`（7 类） | `knowledge.json` 节点 | 直接搬；保留"推导值"标记 | 推导错误无法自动发现 |
| `wrong_questions` 行 | `Attempt` / `WrongItem` | `q_key` → `legacyKey` 反查；`wrong_count` 累加为计数；`stem` **丢弃**（见 §7） | 云端 `stem` 是占位文本 |
| `quiz_mastery` 行 | `Progress`（ mastered 集合） | 只有"做对过"这一事实，无时间 → `completedAt: null` | 时间线无法还原 |
| `exam_records` 行 | `Session`（模考记录） | `detail.items[].k` → 题键；`s` 为得分；`duration_sec` 保留 | 无逐题作答内容，只有得分 |
| `drill_progress` 行 | `Session`（练习会话） | `q_keys[]` → 题 ID 数组；`idx/res` 保留 | `res` 为位串，需确认编码 |

## 7. 已知坑（S1 会踩，先写在这里）

1. **云端错题只有占位题干**。`wrongOf()`（756–758 行）因为"题干含代码会被网关安全策略拦截"，只上传 `TNAME[q.type] + " " + q.no + " 题"`，真实题干靠前端题库还原。→ 迁移器**不能**从云端恢复题干，必须用 `q_key` 回查题库。
2. **`exam_records.detail` 不含答案与对错**，只有 `{k, s}`。想要逐题复盘，旧数据里没有，S1 不要承诺。
3. **`blank` 的 `answer` 不是 `blanks` 的连接**，单空题常带括号注释（`["Web"]` vs `"Web（万维网）"`）。迁移取 `blanks`，但旧 UI 判分可能依赖 `answer`（`blankOk()` 做了归一化容错），要读一遍判分函数再决定。
4. **`app` 填空题的空位编号会跨文件重复**，唯一编号 89 / 字面标记 97。任何"按标记数计分"的实现在迁移后都会算错。
5. **`no` 不是稳定标识**。题库任何增删都会让 `q_key` 语义漂移，这是最大的静默风险。
6. **`quiz_mastery` 无 `updated_at`**，无法判断"什么时候掌握的"，S4 的统计要另想办法（例如用 `exam_records` 的时间近似）。

| 项 | 为什么没验 | 交给谁 | 怎么验 |

| `drill_progress.res` 编码 | 代码只存不解析（`res` 直传） | S1 T1-4 | 读 `save_drill_progress` 的服务端实现或反推位串长度 |
