## 1. 阶段目标

**目标陈述**：把本地优先的通用版接上 WorkBuddy Cloud（不破坏旧表），完成旧云数据与浏览器本地数据的**增量迁移与对账**，补齐 PWA、可访问性与安全检查，最后以可回退的方式替换正式入口。

**可衡量目标**

| 编号 | 指标 | 目标值 | 验证方式 |
| --- | --- | --- | --- |
| G6-1 | 云表与 RLS | V2 五表建立，用户隔离生效，匿名不可读写 | 双账号交叉验证 |
| G6-2 | 迁移完整性 | 旧云记录 + 本地记录按用户/表对账，差异 0 | 对账表 |
| G6-3 | 游客数据不丢 | 未登录时期的错题/进度在登录后按提示合并，无覆盖 | 合并用例 |

## 2. 范围边界

**本阶段做**

- 云 V2 五表：`attempts`、`question_progress`、`practice_sessions`、`exam_records_v2`、`user_preferences`
- RLS 策略：真实用户隔离，显式排除匿名 `anon`
- 接入现有认证（沿用旧版登录方式与 SDK 经验，通过适配器隔离）
- 迁移：备份与检查点 → 短暂停写 → 增量 → 幂等写入 → 分用户/表对账 → 切换写入
- 浏览器 `localStorage` 旧数据转换（保留原键备份）
- PWA：Service Worker 缓存、安装能力、数据备份入口
- 可访问性：移动端/桌面端、键盘操作、焦点管理、屏幕阅读器基础检查、移除禁止缩放
- 构建、性能、异常、安全检查
- 候选 Release → 小范围切换 → 正式 `general-v1.0.0`

**本阶段不做**

- 不新增功能特性（发现的需求一律进 S7）
- 不做 NAS 备份（方案定为阶段二，稳定后按需接入）
- 不清理旧云表（保留只读备份，稳定后再决定）
- 不在 GitHub Pages 上宣称完整可用（未配置合法 Origin/回调前不替换正式入口）
- 不做多端（S8/S9）

## 5. 迁移 Runbook（照着做，不即兴发挥）

> 原则：**先备份与检查点，再短暂停写；增量幂等写入；按用户/表对账；确认后才切换写入方向。**

| 步骤 | 动作 | 通过判据 | 失败处理 |
| --- | --- | --- | --- |
| 1 | 备份：旧云表全量导出 + 浏览器本地数据导出 | 导出文件可打开、条数记录在案 | 停止，不进入下一步 |
| 2 | 记录检查点：记下停写时刻与各表最大时间戳/条数 | 检查点数值写入对账表 | 停止 |
| 3 | 旧版短暂停写（维护提示） | 停写窗口内无新写入 | 缩短窗口或改期 |
| 4 | 读取检查点之后的增量 | 增量条数与旧表变化一致 | 停止，排查漏读 |
| 5 | 幂等写入 V2（`attempts` 用稳定幂等 ID） | 重复执行不产生重复行 | 回滚本步写入 |
| 6 | 按用户/表对账 | 每用户、每表条数与内容校验一致 | 列出差异清单，定向补写 |
| 7 | 切换新版写入，旧表置为只读备份 | 新版写入正常、旧表无写入 | 立即回退到旧版写入并保留新版数据 |

**回退纪律（必须写进 Release 说明）**

- 回退前**先处理新版已产生的新写入**（导出/同步回旧结构），禁止直接切回旧版而丢失这段时间的数据。
- 旧表保留只读备份，确认稳定后再决定是否清理。
- 明确"观察期"长度与判定标准，观察期内不做清理动作。

## 7. 验收标准

### A. 云与安全

- [ ] 五表结构与 `core` 契约一致，字段无漂移
- [ ] 账号 A 无法读取账号 B 的任何记录（逐表验证）
- [ ] 匿名 `anon` 被显式拒绝，不是"默认就查不到"
- [ ] 请求体只含题目 ID 与结果，不含题干/代码全文
- [ ] 无凭据、令牌出现在前端可读位置

### B. 迁移与对账

- [ ] 迁移演练至少完整跑通一次，差异项全部有解释
- [ ] 正式迁移后，按用户/表对账差异为 **0**
- [ ] 迁移可重复执行，不产生重复记录
- [ ] 浏览器 `localStorage` 旧数据转换后，原键备份保留
- [ ] 游客数据合并前有预览与确认，合并后可核对条数

### C. 离线与性能

- [ ] 断网时可打开应用并刷已缓存题库
- [ ] 有明确的"数据已更新/需要刷新"提示，不静默使用过期缓存
- [ ] 冷缓存下首屏内容 3 秒内可见（本地网络条件记录在案）
- [ ] 无控制台未处理异常

### D. 可访问性

- [ ] 仅用键盘可完成一题并查看解析（Tab 顺序合理、焦点可见）
- [ ] 页面允许缩放，未被禁止
- [ ] 主要按钮与输入有可读标签（屏幕阅读器基础可用）
- [ ] 移动端安全区适配保留，桌面端布局不是拉伸的手机卡片

### E. 发布

- [ ] `legacy-ci` 与 `general-ci` 同时为绿
- [ ] `general-dev` 合并到 `main`，`rc.1` 小范围验证通过后打 `general-v1.0.0`
- [ ] 旧 Release 与回退步骤经过演练
- [ ] Release 说明含功能清单、迁移结果、回退方式
- [ ] 正式入口已切换，旧版仍可访问（回退入口保留）

### F. 关键场景（Given / When / Then）

1. **用户隔离**
   Given 账号 A 与账号 B 各有记录，When 以 A 登录并尝试查询 B 的 `attempts`，Then 返回 0 条而非 B 的数据。
2. **游客合并不覆盖**
   Given 游客本地有 30 条记录、账号云端已有 20 条，When 登录并确认合并，Then 云端变为两集合的并集（同幂等 ID 去重），无任何一方被整体覆盖，且合并前有预览数字。
3. **增量不漏**
   Given 检查点记录在某时刻，When 旧版在该时刻后新增了 3 条成绩再停写，Then 迁移后 V2 含这 3 条，对账差异为 0。
4. **重复迁移不重复**
   Given 迁移已执行一次，When 再次执行同一批数据，Then 记录总数不变。
5. **回退不丢新数据**
   Given 切换后新版已产生 10 条记录，When 决定回退旧版，Then 先将这 10 条导出/回写到旧结构，再切回，用户数据无丢失。
6. **离线恢复**
   Given 已安装 PWA 且题库已缓存，When 断网打开应用并答 5 题，Then 5 题可作答，恢复网络后记录上行且不重复。
7. **键盘可用**
   Given 使用键盘用户，When 从首页开始一题并查看解析，Then 全程无需鼠标，焦点始终可见。

### G. 不可接受的情形

- 未做对账就宣布迁移成功
- 用"应该都一样"代替逐表条数核对
- 游客合并直接以云端覆盖本地（或反之）
- `anon` 仅靠前端不请求来"保证"隔离
- 回退时直接切回旧版，未处理新版新增数据
- 在未配置合法 Origin/回调的情况下宣称云功能完整可用

## 9. 阶段特有风险与应对

| 风险 | 触发信号 | 应对 |
| --- | --- | --- |
| 停写窗口过长 | 用户抱怨无法使用 | 提前演练时长；窗口内只做机械执行，不做调试 |
| 漏读增量 | 对账条数差若干 | 以检查点时间戳为准，不靠"大概停写后没新数据" |
| RLS 配置遗漏某表 | 某表可跨用户读到 | 逐表策略清单，配一条测一条 |
| Origin/回调不匹配 | 登录在正式域名失败 | 切换前在真实域名验证登录，不接受本地通过 |
| 云额度超限停服 | 调用报错/暂停 | 用量估算 + 监控 + 告警 + 全量导出能力 |
| 无障碍成为"以后再说" | 清单长期空白 | 本阶段门禁强制，未过不进 S7 |
| 回退路径未演练 | 出事时才发现不可逆 | 演练作为门禁硬项 |

## 10. 回退方案

1. **发布回退**：正式入口切回旧版 Release，旧版仍在 `main` 历史中且可构建。
2. **数据回退**：先导出新版写入 → 转换为旧结构 → 回写 → 再切回；禁止直接覆盖。
3. **部分回退**：仅回退云同步（前端回本地模式），保留新 UI；适用于云端故障而本地正常。
4. **观察期规则**：观察期内不清理旧表、不删旧 Release、不做不可逆操作。
