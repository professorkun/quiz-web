> 本文是权威定义：方案（做什么、为什么）+ 执行计划（按什么顺序做、怎么验收）。

| # | 规格 | 现状判定 |

| G-1 | 登录后的网页 = 与未登录一致：**无题库的空态页 + 上传题库按钮**（不预置任何题库） | 代码已满足（空壳化 `f997807`）；线上已是空壳构建，但启动写入缺陷（§2 缺陷 D-A）导致第二次打开即「无法启动」，**已修复**，差在重新发布 |

## 3. 方案设计

### 3.1 G-1 空态不变形（部署层）

当前代码已实现「无题库 → `EmptyState`（含上传按钮）；导入后 → 功能页」的守卫（`App.tsx` 空态守卫 + `PlatformProvider` 空数组不再抛错）。**不需要新代码**，需要把空壳版构建并重新发布到保留域名（与云 endpoint 同域，OAuth Origin 依赖它）。

- 上传按钮文案统一为「**上传题库**」（现为「选择题库包文件」，语义相同，措辞对齐用户语言，属微调）。
- 登录前后页面形态完全一致；登录只是头部账号卡状态不同。

### 3.2 G-2/G-3 保存路由（核心改动）

在两个上传入口（`EmptyState.tsx` 首屏、`ImportExport.tsx` 我的页）**共用一条保存路由**，按登录态分流：

```
parseBankJson 校验通过 → saveBankRouted(bank)
    ├─ auth.getUser() == null（未登录）
    │     └─ banks.saveImportedBank(bank)          ← 现状，存本地 IndexedDB
    └─ auth.getUser() != null（已登录）
          ├─ 云端 upsert question_banks(owner, bankId, payload)   ← 新增
          ├─ banks.saveImportedBank(bank)          ← 仍写本地，作离线缓存
          └─ 云端写失败 → 本地照常保存 + 明确提示「云端保存失败，已存本地」（绝不丢题）
```

原则：
- **本地始终写**（离线可用、练题性能），云端是登录态下的持久化与跨设备源。
- **不静默降级**：云端失败必须可见（沿用「宁可拒绝不静默」的既有纪律）。
- 题库包含题干/代码正文——见 3.4 WAF 前置探测，这是本方案最大的技术不确定点。

### 3.3 云端题库存储（新表）

沿用五表的建表/RLS 套路（T6-1/T6-2 已验证的做法）：

```sql
CREATE TABLE question_banks (
  owner_id       uuid        NOT NULL DEFAULT auth.uid(),
  bank_id        text        NOT NULL,
  title          text        NOT NULL,
  question_count int         NOT NULL,
  payload        jsonb       NOT NULL,   -- 完整 quiz.bank 包：manifest + questions + knowledge
  updated_at     timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (owner_id, bank_id)
);
ALTER TABLE question_banks ENABLE ROW LEVEL SECURITY;
CREATE POLICY qbank_owner ON question_banks
  USING (owner_id = auth.uid()) WITH CHECK (owner_id = auth.uid());
REVOKE ALL ON question_banks FROM anon;   -- 与五表同款：匿名零权限
GRANT ALL ON question_banks TO authenticated;
```

- 幂等：`(owner_id, bank_id)` 主键 upsert，同 `bankId` = 覆盖（与本地语义一致）。
- 客户端不发 `owner_id`（服务端 `auth.uid()` 补），沿用同步层既有约定。
- 存储形态备选（Step 1 烟测后定）：**A. DB jsonb**（上式，默认）；**B. 文件存储**（每用户每题库一个对象，manifest 进 DB）——若新云对大 jsonb/代码正文有限制，切 B。

### 3.4 WAF 前置探测（必须先做，不可跳过）

既有五表设计明文规定「落库不含题干/代码正文」（`v2-schema.md` §5，旧云网关拦代码正文）。题库包**天然含**题干与代码。两云不是同一套（旧云 `wbapp-x4curlcgbt2kilpzdqg6lh` vs 新云 `wbapp_g64vX7uZdYwdm0BJTVINDk`），新云对正文的态度**未验证**。

→ **Step 1 做真实写入烟测**：往新云写 1 行含代码正文的 jsonb（十几行 Java 代码 + 题干），读回比对 + 同步层真实 push 一次含 `code_blank` 答案的 attempt。被拦就切文件存储方案，不硬闯。

### 3.5 读取与展示（登录态）

- 登录后进入应用：**先拉云端题库清单**（`question_banks` 按 `updated_at` 取全量 manifest，payload 惰性拉取），再跑学习记录 `syncAll`（顺序固定：**先题库后记录**，否则记录回灌时题库还不在，统计投影会空）。
- 云端题库落地为本地缓存（复用 `saveImportedBank` 通道），离线可练。
- **决策点 D-1（见 §4）**：云端题库登录后自动加载显示（推荐） vs 手动「从云端载入」。

### 3.6 上传入口的行为矩阵（最终形态）

| 登录态 | 页面形态 | 上传后保存位置 | 云端失败时 |
| --- | --- | --- | --- |
| 未登录 | 空态 + 上传题库按钮 | 仅本地 | 不适用 |
| 已登录（无题库） | 空态 + 上传题库按钮 | 云端 + 本地缓存 | 本地保存 + 显式提示 |
| 已登录（已有云端题库） | 功能页（题库列表含云端题库） | 同上 | 同上 |

## 4. 决策点（执行前请拍板）

| # | 问题 | 推荐 | 影响 |
| --- | --- | --- | --- |
| **D-1** | 登录后，云端已存的题库**自动加载显示**，还是**手动「从云端载入」**？ | **自动加载**（登录即见自己的题库，跨设备才有意义） | 决定 §3.5 实现；若选手动，空态+上传按钮在登录后恒显 |

| **D-3** | 登出后，本地缓存的云端题库**保留还是清理**？ | **保留**（与学习记录同策略；UI 标「来自云端」） | 决定 Step 7 |
| **D-4** | 两台设备各传了同 `bankId` 的题库包（内容不同）？ | **LWW（`updated_at` 新者胜）**，与五表 progress 一致 | 冲突规则一句话，实现里只留一条 |

## 6. 风险与回退

| 风险 | 处置 |
| --- | --- |
| 新云 WAF 拦代码正文（Step 1 命中） | 切文件存储方案（3.3-B）；题库包本就是单 JSON，天然适配对象存储 |
| 题库包体积（含讲义可达 MB 级） | Step 1 烟测带真实大小样本；必要时 payload 分片或讲义独立存储 |
| 云写失败导致用户以为已保存 | 3.2 明确降级提示；本地永远先写成功再尝试云 |
| 同步层与题库拉取顺序颠倒 | 3.5 固定「先题库后记录」；syncAll 前置题库拉取 |
| 分享链接被网关拦（「链接不完整」） | 裸域名不带 `?sharecode=` 会报此错，属正常网关行为；用应用卡/管理页给出的完整分享链接访问 |
| 不可逆动作（建表/RLS/发布） | 建表语句先在方案定稿、执行留痕；发布沿用 T6-12 runbook |

## 7. 明确不做（本期边界）

- 不动旧云四表（只读备份）；不做旧数据迁移（题库/旧数据已在空壳化时移除，Step 8 作废的迁移不再恢复）。
- 不改学习记录五表结构与同步语义（题库是**独立第六条链路**，只在拉取顺序上衔接）。
- 不做小程序/Android 端（S8/S9 另线）。
- 不引入题库市场/分享链接（超出用户规格）。
