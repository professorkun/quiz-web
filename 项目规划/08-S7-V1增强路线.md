# 08 · S7 — V1 之后的增强路线

| 项 | 内容 |
| --- | --- |
| 阶段编号 | S7 |
| 阶段性质 | 增强池（不是"一次做完的阶段"，而是"按证据逐项取用"的清单） |
| 分支 | 每项一条 `feat/general-*` → PR 到 `main`（S6 后 `main` 即通用版） |
| 阶段标签 | 每项单独打，如 `e1-editor` |
| Milestone | S7 - 增强（按项） |
| 前置阶段 | S6（通用版 V1 已上线并稳定） |
| 后置阶段 | S8 / S9（不并行） |
| 工作量 | 按项（见下表） |

---

## 1. 阶段目标

**目标陈述**：V1 上线后，把"想做的功能"变成"有证据才做的功能"。本阶段不设统一完工日期，设的是**准入条件**与**单体验收标准**——避免通用化演变成无限功能列表。

**为什么这么设计**：方案 §11 已把"通用化膨胀成无限功能列表"列为头号风险。增强项最大的成本不是开发，而是**维护面扩大与数据契约反复变更**。所以每项都必须先满足准入条件（有真实使用证据），再谈实现。

**阶段级目标**

| 编号 | 指标 | 目标值 | 验证方式 |
| --- | --- | --- | --- |
| G7-1 | 每项有证据 | 100% 的启动项能指出触发它的真实使用场景 | 事项卡"启动证据"栏 |
| G7-2 | 契约不反复 | 每项启动前评估是否改数据契约，改动走版本升级 | ADR + `schemaVersion` |
| G7-3 | 不回归 | 每项合入后 `general-ci` 绿，V1 核心闭环用例不回退 | CI + 回归清单 |
| G7-4 | 不并行多端 | S7 进行中不同时开 S8/S9 | 分支与任务记录 |

---

## 2. 排序原则

按**实际使用价值**排序，不按技术趣味，也不同时开发（方案 §9 S7）。判断顺序：

1. **是否解决你每天都在遇到的问题**（自用频率）
2. **是否阻塞其他更有价值的事**（依赖关系）
3. **是否引入不可逆的数据契约变更**（成本与风险）
4. **是否有替代的轻量做法**（能配置解决就不写功能）

## 3. 增强事项卡

### E1 · 可视化题目/题库编辑器与批量编辑

| 项 | 内容 |
| --- | --- |
| 解决什么 | 目前新增题目依赖 Markdown/JSON 导入，改题要动源文件 |
| 启动证据 | 一个月内至少 3 次"想直接改一道题但嫌麻烦" |
| 范围 | 单题编辑、批量改标签/主题/难度、保存前校验、导出为标准格式 |
| 不做 | 富文本协同编辑、版本对比合并、多人同时编辑 |
| 验收 | 编辑后导出 → 再导入无差异；非法内容被拦并定位；不绕过 Schema 校验 |
| 风险 | 编辑器成为第二套写入口，导致数据来源分裂 → 强制"编辑器输出 = 标准包格式" |
| 量 | L |

### E2 · 自定义题单、学习计划、每日目标

| 项 | 内容 |
| --- | --- |
| 解决什么 | 缺乏"刷什么"的路径，容易随手刷而不成体系 |
| 启动证据 | 出现"不知道该刷哪些"的实际困扰，或已有明确考试日期 |
| 范围 | 手动题单、按主题生成题单、每日目标与完成度、简单学习计划 |
| 不做 | 智能排期、社交打卡、排行榜 |
| 验收 | 题单可保存复用；每日目标达成度可统计；与 S4 复习不冲突（不重复计算） |
| 风险 | 与复习调度打架 → 题单只是"选题来源"，不改变复习状态机 |
| 量 | M |

### E3 · 富媒体 ZIP 导入与图片资源管理

| 项 | 内容 |
| --- | --- |
| 解决什么 | 含图片/附件的题库无法完整导入 |
| 启动证据 | 至少一次因图片缺失而放弃导入某题库 |
| 范围 | ZIP 包规范（题目 + 资源目录）、资源校验、存储与引用、缺图提示 |
| 不做 | 视频流、在线转码 |
| 验收 | 含图题库导入后图片可显示；缺失资源有清单；导出可还原 |
| 风险 | 包体积膨胀（小程序端约束）→ 资源按需拉取，不默认全量打包 |
| 量 | M |

### E4 · 基于真实复习记录的 ts-fsrs

| 项 | 内容 |
| --- | --- |
| 解决什么 | 1/3/7 天固定间隔对难易不同的题不敏感 |
| 启动证据 | 累计至少数百条复习记录，且能指出"固定间隔明显不合适"的具体题 |
| 范围 | 接入 `ts-fsrs`，Again/Hard/Good/Easy 与作答结果和主观自评映射 |
| 不做 | 首版即上算法（方案已明确后置） |
| 验收 | 可由事件重算排期；可与旧规则并行对比；切换可回退到 1/3/7 |
| 风险 | 参数不清导致复习负担暴增 → 先影子运行（只算不生效），比对后再切换 |
| 量 | M |

### E5 · 弱项推荐与自适应练习

| 项 | 内容 |
| --- | --- |
| 解决什么 | 不知道薄弱点在哪，练习效率低 |
| 启动证据 | 已有足够覆盖率数据，且 E4 已稳定 |
| 范围 | 按知识点正确率排序推荐、错因聚类、"今日建议" |
| 不做 | 复杂 IRT/自适应测试模型 |
| 验收 | 推荐理由可解释（给出依据数据）；可关闭；不改变既有记录 |
| 风险 | 黑箱推荐降低信任 → 每条推荐必须展示依据 |
| 量 | M |

### E6 · AI 辅助出题 / 解析

| 项 | 内容 |
| --- | --- |
| 解决什么 | 造题与写解析耗时 |
| 启动证据 | 有明确的批量造题需求（如整章新增） |
| 范围 | 生成草稿 → **人工审核后入库**；保留来源标记 |
| 不做 | AI 直接写入题库、AI 批改主观题（方案已排除） |
| 验收 | 未经审核的生成内容无法进入正式题库；生成内容带来源标记 |
| 风险 | 错误解析污染学习数据 → 审核为硬门，且不入复习统计直到通过 |
| 量 | M |

### E7 · 教师端、班级与权限

| 项 | 内容 |
| --- | --- |
| 解决什么 | 多人/班级使用场景 |
| 启动证据 | 出现真实的第二个使用者群体需求（不是"以后可能"） |
| 范围 | 按需最小实现；若需求变重，重新评估是否该改用学之思类系统 |
| 不做 | 付费、权限矩阵、考试防作弊 |
| 验收 | 角色隔离明确；不破坏个人使用路径 |
| 风险 | 走向"考试平台"，与方案定位冲突 → 启动前必须重新确认产品定位 |
| 量 | L（或不做） |

## 4. 阶段门禁（适用于每一个增强项）

每项合入前必须全绿，缺一不进：

- [ ] G1 数据：若改契约，`schemaVersion` 升版且有向上迁移；旧数据可读
- [ ] G2 功能：本项验收标准逐条通过，且给出证据
- [ ] G3 工程：`general-ci` 绿；新增逻辑有单测；无未处理异常
- [ ] G4 可回退：功能可整体关闭或配置回退，不破坏已有记录
- [ ] V1 核心闭环回归通过（游客练习 / 错题复习 / 模考 / 导入导出）
- [ ] 文档与 ADR 已更新

---

## 5. 阶段特有风险与应对

| 风险 | 触发信号 | 应对 |
| --- | --- | --- |
| 增强项无限扩张 | 待办列表只增不减 | 每季度清一次池子，删掉无证据项 |
| 数据契约被反复改 | 每项都要动 `Attempt`/`Progress` | 契约变更需 ADR + 版本升级，评估历史数据 |
| 增强打乱 V1 稳定 | 上线后 bug 率上升 | 每项独立分支、独立验收、可单独回退 |
| 提前并行多端 | 同时开 S8/S9 | 方案明确不并行，违反须登记理由 |
| 为功能而功能 | 说不出"谁在什么场景用" | 准入条件不满足就不启动 |

---

## 6. 回退方案

1. 每项独立标签，回退即 `revert` 该 PR。
2. 涉及数据结构的，回退时保留新字段（不删列），只停用读取路径。
3. 增强项一律提供功能开关（配置级），出问题先关开关再排查。
