## 1. 阶段目标

**目标陈述**：用 Capacitor 把 `apps/web` 的构建产物包装成可安装的 Android 应用，用 SQLite 实现移动端存储适配器，并复用同一套 `core` 与云端表——**一行判分逻辑都不重写**。

**可衡量目标**

| 编号 | 指标 | 目标值 | 验证方式 |
| --- | --- | --- | --- |
| G8-1 | 逻辑零重复 | 判分/选题/复习全部调用 `packages/core` | 代码扫描 + 单测共用 |
| G8-2 | 离线可用 | 飞行模式下可刷已下载题库 | 手测 |
| G8-3 | 同步不重复 | 一次完整练习上行后云端无重复记录 | 云端核对 |
| G8-4 | 数据互通 | Android 与 Web 同一账号数据一致 | 双端交叉 |
| G8-5 | 可安装 | 签名包可侧载安装并正常运行 | 真机安装 |

---

## 2. 范围边界

**本阶段做**

- Capacitor 包装 `apps/web`，不重写 UI
- Android 侧 `StorageAdapter`（SQLite 实现）
- 离线题库下载与本地缓存
- 登录：微信 OpenSDK 或邮箱，复用云端同一套 `AuthProvider`
- 图标、启动页、返回键行为、安全区适配、网络异常提示
- 签名包构建，先侧载验证，再决定是否上架

**本阶段不做**

- 不重写任何页面与领域逻辑
- 不做三端并行（小程序留 S9）
- 不做上架所需的软著/备案材料（除非确定上架）
- 不新增 Web 端没有的功能
- 不引入独立后端

## 6. 验收标准

### A. 逻辑与数据

- [ ] 判分、选题、复习调度全部来自 `packages/core`，Android 侧无副本
- [ ] Android 端 `StorageAdapter` 通过 Web 端同一批存储用例（等价语义）
- [ ] 同一账号在 Web 与 Android 上看到相同的错题、进度与成绩
- [ ] 一次完整练习（10 题含 3 错）上行后，云端记录不重复

### B. 离线

- [ ] 飞行模式下可打开应用并刷已下载题库
- [ ] 未下载的题库在离线时给出明确提示，不白屏
- [ ] 恢复网络后离线产生的记录自动上行且不重复

### C. 平台体验

- [ ] 图标与启动页正常，无默认占位
- [ ] 返回键行为符合 Android 习惯（不误退出、不卡死）
- [ ] 安全区与状态栏适配正常，页面不被遮挡
- [ ] 网络异常时提示可读，可重试

### D. 关键场景（Given / When / Then）

1. **离线刷题**
   Given 已下载 JavaWeb 题库，When 开启飞行模式并答完 10 题，Then 全部可作答并判分，记录保存在本地。
2. **恢复同步**
   Given 上述 10 条离线记录，When 恢复网络并触发同步，Then 云端新增恰好 10 条，重复同步不增加。
3. **跨端一致**
   Given 在 Android 上答错第 5 题，When 在 Web 端同一账号打开复习页，Then 第 5 题出现在错题列表，复习间隔一致。
4. **登录过期**
   Given 登录态过期，When 触发同步，Then 提示重新登录，本地记录保留不丢。

### E. 不可接受的情形

- 为省事在 Android 侧复制一份判分逻辑
- 离线记录上行产生重复
- 未下载题库时离线直接崩溃
- 返回键导致应用直接退出且丢失当前作答

## 8. 阶段特有风险与应对

| 风险 | 触发信号 | 应对 |
| --- | --- | --- |
| 三端逻辑分叉 | Android 侧出现判分代码 | CI 静态检查：`core` 之外禁止判分实现 |
| 存储语义不一致 | 同用例在 Android 通过但 Web 失败 | 用同一批用例跑两端 |
| 包体积失控 | APK 远超预期 | 题库按需下载，不打进包 |
| 上架成本低估 | 需要软著/备案才发现 | 侧载先行，上架单独评估 |

---

## 9. 回退方案

1. 不上架即回退：停止分发 APK，Web 与 PWA 不受影响。
2. 数据回退：Android 写入的均为标准云端记录，Web 可直接读取，无需迁移。
3. 版本回退：保留上一版签名包，供侧载用户回装。
