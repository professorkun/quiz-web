# 12 · 给 AI 的执行协议

> 配套文件：`00-总览`（门禁与状态表）、`01`~`10`（各阶段计划）、`11-模板`（新增阶段）
> 核心前提：**AI 不跨会话记忆**。所以执行顺序的载体不是"对话上下文"，而是这三个文件的当前状态。

---

## 0. 一句话原则

**一次会话 = 一个任务块 = 一份可复现的证据。阶段门禁必须由人拍板，不能由 AI 自己宣布通过。**

---

2. S6 之前不接云、不碰真实用户数据。
3. S7 / S8 / S9 三者不并行。

## 2. 单次会话的 8 步循环

| 步 | 动作 | 产出 |
| --- | --- | --- |
| 1 | **只读三处**：`00` 的 §8 状态表与 §10 风险、当前阶段文件、上一阶段 §11 收尾记录 | 当前上下文 |
| 2 | **报状态**：当前阶段、已完成任务 ID、下一个任务 ID | 一句话对齐 |
| 3 | **先声明判据**：把该任务的"完成判据"与"怎么验证"复述出来 | 避免做完再编标准 |
| 4 | **只做一个任务块**（`T{n}-x`），做完即停 | 一处可审查的改动 |
| 5 | **立即验证**：跑测试/命令/对账，把输出留下 | 证据 |
| 6 | **写回文件**：阶段文件 §11 收尾记录、`00` §8 状态表 | 跨会话记忆 |
| 7 | **汇报四件事**：改了什么 / 证据是什么 / 有什么阻塞 / 下一步是什么 | 可交接的结论 |
| 8 | **停**。等人决定继续还是先验收 | — |

> 第 3 步和第 6 步是这套协议里最容易被跳过、也最值钱的两步：前者防止"标准的漂移"，后者防止"下次会话从零猜"。

---

## 3. 阶段收尾（必须人工参与）

阶段内最后一个任务块完成后，按这个顺序走，**不许合并成"顺手打个标签"**：

1. AI 逐条跑阶段文件 §7 门禁清单，每条附证据；
2. 人工判定：全绿 / 有条件通过 / 未通过（AI 只提供证据，不下结论）；
3. 打阶段标签；
4. 更新 `00` §8 状态表与 §9 变更登记；
5. 把未完成项移入下一阶段待办或 S7，不夹带；
6. 才允许开下一阶段的第一个任务块。

---

## 4. 一句话启动模板（直接复制给 AI）

| 场景 | 你只需要说 |
| --- | --- |
| 开始一个阶段 | 「按 `项目规划/01-S0-Git基线与旧版维护.md` 执行 T0-2，完成判据是文件里写的那条，做完更新收尾记录」 |
| 接着上次做 | 「读 `00` §8 和当前阶段 §11，继续下一个未完成任务，仍然一次只做一个」 |
| 要求验收 | 「跑 `03-S2…` 的 §7 门禁清单，逐条给证据，不通过就只列出差距，不要顺手改代码」 |
| 卡住了 | 「你在 T1-4 卡在哪一步？给出两个可选解法及各自代价，我来选」 |
| 要回退 | 「回退到标签 `s2-practice-slice`，先说明这次回退会丢掉哪些已完成工作」 |
| 问进度 | 「读 `00` §8，汇报当前阶段、已完成任务、下一个任务、阻塞项」 |

**反例（不要这样说）**：「把 S1 全部做完」「按规划把项目做出来」——这会让 AI 把 6 个任务块压缩成一次输出，验收标准被跳过，证据变成"应该没问题"。

---

## 5. 六件事 AI 不代劳

这些动作要么涉及不可逆的外部写入，要么需要人的判断，必须由你操作或明确授权：

1. 建 GitHub 仓库、推送、开分支保护；
2. 云端建表、配置 RLS、执行真实迁移的"停写"决策；
3. 用真实账号验证登录与用户隔离（AI 没有你的登录态）；
4. S6 对账结果的最终确认（数字对不上时停不停，是人决定）；
5. 签名打包、上架、类目与备案材料；
6. 题库内容版权与开源许可证的判断。

---

## 6. 什么叫"做完"：三种证据

| 证据类型 | 示例 |
| --- | --- |
| 命令输出 | `pnpm -F core test` 全绿；构建后题量 `147` |
| 测试名 | `session-restore.spec.ts > 刷新后题序与选项序一致` |
| 对账数字 | 迁移前后 `attempts` 条数：1,204 → 1,204，差异 0 |

**不接受**：「已完成」「已实现」「应该没问题」「测过了」。判定句必须能被另一个人重跑。

---

## 7. 五种反模式

1. **一次塞整阶段** → 任务块被合并，验收被跳过。
2. **跨阶段抢跑** → S1 没过就写页面，S4 没稳就接云。
3. **无证据验收** → AI 自己说通过，等于没验收。
4. **让 AI 猜旧版行为** → 旧版有真实行为基线（模考卷面、空位计分、冒烟项），必须去读代码或跑一遍，不靠印象。
5. **把"通过"的判定权交给 AI** → 门禁是人的决定，AI 只出证据。

---

## 8. 每次开机先看这张表

不另建进度表，直接用 `00` §8。开工前 30 秒确认三件事：**当前阶段是什么、上一阶段是否全绿、下一个任务 ID 是哪个**。
