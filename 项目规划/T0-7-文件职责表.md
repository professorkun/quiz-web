## 3. 运行依赖（看着冗余，删了就坏）

| 文件 | 判定 | 为什么不能删 |
| --- | --- | --- |
| 根目录 `sdk.js` | ⚪ 保留勿删 | `build_html.py` 会生成/内联它，并作为运行时兜底。它与 `_build/cloud-sdk.js`、`题库网页/sdk.js` **三份内容必须一致**（CI 校验） |
| `题库网页/sdk.js` | ⚪ 保留勿删 | 发布目录自带的 SDK 副本，缺了线上页面报错 |
| `.gitignore` / `.gitattributes` | ⚪ 保留勿删 | 前者挡敏感文件与 `.workbuddy/`；后者统一 LF 存储，否则 CI 在 Linux 上重建会因 CRLF 误判 |
| `.workbuddy/` | ⚪ 保留勿删（且**不入库**） | 工作区数据目录：`memory/` 是跨会话记忆、`applications.yaml` 是发布登记。**只忽略、不删除** |
| `.wbapp_*.genie` | ⚪ 保留勿删（且**不入库**） | 本机发布凭据（`appId` / `localDir` / `entryHtml`）。删了需重新发布获取 |

## 6. 依赖关系（删东西前先看这张图）

```
JavaWeb期末全题型题库.md
   └─→ build_json.py ─→ _build/data.json ─┐
                                          ├─→ build_html.py ─→ JavaWeb期末题库.html
_build/template.html ─────────────────────┤                   └→ 题库网页/index.html
_build/cloud-sdk.js ─ 内联 ────────────────┤
sdk.js ───────────── 内联 ────────────────┘

ci_check.py ── 校验以上全部产物与一致性（不参与生成）
```

**唯一允许的"删除"是删除构建中间产物后重建**（`_build/data.json`、两份 HTML），且必须立刻重跑构建，让 `git status` 恢复干净。

## 7. 变更流程（与方案 §5.8 一致）

| 想做什么 | 走哪条路 |
| --- | --- |
| 改题库内容 | `content/javaweb-*` 分支 → 只改 Markdown → 重跑构建 → PR 到 `main` → 合并到 `general-dev` |
| 修旧版 Bug | `fix/legacy-*` 分支 → 修 → `python3 _build/ci_check.py` 全绿 → PR 到 `main` |
| 加通用新功能 | 只进 `general-dev` / `web-v2/`，**不往旧版单文件里加** |
| 发布 | 只发 `main` 的 `题库网页/`，发布前 `ci_check.py` 全绿 |
| 删除任何文件 | 先查本表第 1–5 节；属 🔴/⚪ 的一律先问，不要"看起来没用就删" |
