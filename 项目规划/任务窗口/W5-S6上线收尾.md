## 4. 执行步骤

1. **备份与检查点**：导出旧云表与本地全量 JSON，记录检查点时间与 hash；确认可回退路径存在。
2. **短暂停写**：按 runbook 约定窗口停写，避免切换期旧版继续写入。
3. **增量迁移**：把真实旧数据迁到新 uid（T6-6），按用户/表逐项对账，差异 0 才算过。
4. **真实同步与跨设备验证**：登录后上行/下行各一次，重复同步不产生重复记录；跨设备读一致。
5. **游客合并**：未登录时期的错题/进度按提示合并，无覆盖；先备份再合并。
6. **回退演练**：按 `07` §6 实际走一遍回退步骤，记录每步结果与耗时，**失败可停可退**。
7. **双 CI 绿**：`legacy-ci` 与 `general-ci` 都跑通；若 `pnpm verify` 复现构建期清空 `dist/` 被安全策略拦截，按 INT 文件 §4 的"改名不删源码"方式处置并记录。
8. **Release 记录**：候选 Release → 小范围切换 → `general-v1.0.0`；产出「S6 状态数据」给 W6。
9. 全过程写进 `w5-s6-closeout.md`，按 §9 回执。

## 8. 本窗口特有风险

| 风险 | 缓解 |
| --- | --- |
| 真实数据不可逆损坏 | 备份 → 检查点 → 短暂停写 → 分步对账 → 可停可退；不清理旧表 |
| 云额度不透明导致停服（R-14） | 资源点估算 + 用量监控 + 全量 JSON 导出能力 |
| 把家宽/NAS 当正式入口（R-15） | 正式入口只用静态托管 + 云端 |
| 双线切换期旧版仍写入导致漏数据（R-04） | 检查点 → 停写 → 最终增量 → 分用户对账 |
| 构建期 `emptyOutDir` 被拦截，误删源码 | 只改名产物目录，禁止 `rm -rf` 源码或清空 `build/` |
| 单窗口"通过"但集成红 | 只有 INT 证据表算最终判定 |
