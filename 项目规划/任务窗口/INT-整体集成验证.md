## 4. 执行步骤（9 步）

| 步 | 命令 / 动作 | 通过判据 |
| --- | --- | --- |
| 1 | 确认 P-1 处置完成、工作区无游离草稿 | `git status` 干净或草稿已入版本管理；基线 tag 可追溯 |
| 2 | `node web-v2/packages/content/scripts/build-knowledge.mjs` | 输出 7 篇 / ≥50k 字；与 W2 提交的 `knowledge.json` **字节一致** |
| 3 | `cd web-v2 && pnpm -r build` | 全部包构建成功，无 TS 错误 |
| 4 | `pnpm verify` | 边界扫描 + 扩展点扫描 + 构建 + 空位对账 + 功能对等 + 全量单测全绿 |
| 5 | `python3 _build/ci_check.py`（仓库根） | 旧版 15 项结构自检全绿，两份 HTML 字节一致（旧版未受影响） |
| 6 | `pnpm --filter @quiz/core exec vitest run` 复核契约用例 | C-1～C-5、B-1/B-2 全过；`validateKnowledgeModules(knowledge.json)` 返回 ok |
| 7 | 产物拷到空目录启动，做浏览器实操 | 见 §5 冒烟清单 |
| 8 | 云同步 / 回退 / 双 CI 复核 | 与 `w5-s6-closeout.md` 一致；G6-1～G6-7 逐条有证据 |
| 9 | 汇总证据表 → 交 W6 回填 `00` §8 与 changelog | 证据表无空缺项；未通过项写明责任窗口与回退建议 |

> **第 4 步的已知环境问题（D-06）**：`vite build` 清空 `apps/web/dist/` 时可能触发本机安全删除保护
> （62 个文件 > 50 阈值）。处置方式：**先把产物目录改名再构建**（`dist` → `dist.prev`），
> 之后由负责人决定是否清理旧产物。**禁止 `rm -rf` 源码、禁止清空 `build/`**。
> 处置命令与实际输出必须写进证据表。
