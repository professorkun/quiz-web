## 1. 目标

把"接口长什么样、谁改哪个文件、决策是什么"写成一份**不可随意改的冻结文本**，让六个窗口能基于同一份契约同时开工，而不是互相等代码。

一句话原则：**用冻结的契约文本代替窗口之间的运行时依赖**。

## 2. 负责范围

| 类别 | 路径 |
| --- | --- |
| 白名单（只许新建） | `web-v2/docs/plans/parallel-contract.md`、`web-v2/docs/plans/window-board.md`、`web-v2/docs/reports/w0-freeze-report.md` |
| 允许的操作 | 创建 `integrate/s7-e8` 集成分支、打基线 tag、创建六个窗口分支 |
| 黑名单 | 任何源码、`项目规划/*.md` 既有文档、`docs/adr/**`、任何 `package.json`、`pnpm-lock.yaml`、旧版根目录 |

**三条通用纪律**：新增文件优先；一个 commit 只属于一个窗口；G0 冻结后改接口必须走「契约变更单」→ 更新文本 → 广播全部窗口。

## 3. 输入依赖

| 类型 | 内容 | 缺失时的处理 |
| --- | --- | --- |
| 决断（已定） | **P-1 = 保留草稿**：草稿不撤销、不重写，纳入版本管理后按验收标准补验证 | 打基线 tag 前须确认全部窗口已核对本范围草稿 |
| 决断（已定） | **P-2 = A**：题库页内精读区；`router.ts` / `App.tsx` / `AppShell.tsx` 三方冻结 | 若后续改 B，必须发契约变更单并广播 |

| 环境 | git 可用、能创建分支与 tag | 不可用时改用单窗口串行执行，并在报告里说明 |

## 4. 执行步骤（顺序不可调换）

> **关键顺序**：必须先提交冻结契约，**再**从"含契约的 HEAD"创建窗口分支。
> 若先开分支后写契约，六个窗口分支都读不到 `parallel-contract.md`，全部要 rebase。

1. **先落基线**：`git status` 列出保留下来的草稿，确认各窗口范围的草稿都在；按 P-1 把它们**提交成基线快照**（建议单条 `chore: 阶段前基线快照`），记录 commit hash。此时仍在 `general-dev`。
2. 创建集成分支：`git checkout -b integrate/s7-e8`。
3. 把**已决结论**写入契约文本第 0 节：P-1 = 保留草稿、P-2 = 先按 A（路由冻结），决策人「用户」、日期 2026-11-18；并把「P-1 保留的工作方式」写成一句全员纪律（草稿纳入版本管理、核对差距、不重复重写、不覆盖）。
4. 写 `parallel-contract.md`，最小内容七项：
   - ① P-1 / P-2 结论与决策人；
   - ② TS 类型签名：`KnowledgeModule`（6 个新增可选字段 + `items` 缺省 `[]`）、`KnowledgeSection`、`KnowledgeVideo`、`KnowledgeResource`、`validateKnowledgeModules` 签名与错误路径格式、`parseMediaSource` 签名与 `MediaSource` 全部字段；
   - ③ `parseMediaSource` 行为表：B 站完整链接 / 裸 BV 号 / av 号 / YouTube 三种写法 / mp4 直链 / 相对路径 / m3u8 / 普通网页 / `b23.tv` 短链 / `javascript:` / 空串，逐行给出期望 `kind` 与 `watchUrl`；
   - ④ 导入错误码格式：`[SCHEMA_INVALID] knowledge[i].字段: 说明`；
   - ⑤ 讲义 Markdown 的 front matter 字段表与 `##` 切节规则；
   - ⑥ 14 号 §3 所有权矩阵 + 六个窗口分支名 + 合并顺序；
   - ⑦ 契约变更单流程：发起人 → G0 更新文本 → 广播 → 各窗口确认。
5. 初始化 `window-board.md`（列：窗口 / 分支 / 启动 / 开发中 / 自验通过 / 已合并 / 报告路径 / 备注）。
6. 写 `w0-freeze-report.md`：记录基线 commit、契约文本路径、六个分支、广播对象与时间。
7. **提交冻结件**：把 `parallel-contract.md`、`window-board.md`、`w0-freeze-report.md` 提交到 `integrate/s7-e8`（如 `docs(s7e8-w0): 冻结契约与决策`）。
8. **从含契约的 HEAD 打 tag 并创建六个窗口分支（顺序不可颠倒）**：
   ```bash
   git tag -a s7e8-contract-frozen -m "S7-E8 契约冻结基线"
   git branch feat/s7e8-core-contract  s7e8-contract-frozen   # W1
   git branch content/s7e8-lectures    s7e8-contract-frozen   # W2
   git branch feat/s7e8-lecture-ui     s7e8-contract-frozen   # W3
   git branch fix/s7e8-ui-consistency  s7e8-contract-frozen   # W4
   git branch chore/s6-closeout        s7e8-contract-frozen   # W5
   git branch docs/s7e8-integration    s7e8-contract-frozen   # W6
   ```
9. **真并行必须做工作区隔离**：六个窗口若共用 `F:/001/刷题` 这一个目录，`git checkout` 会互相覆盖，文件所有权矩阵形同虚设。为每个窗口建独立 worktree（目录放在工作区之外，路径避免中文/空格）：
   ```bash
   git worktree add "F:/001/wt-s7e8/w1" feat/s7e8-core-contract
   git worktree add "F:/001/wt-s7e8/w2" content/s7e8-lectures
   git worktree add "F:/001/wt-s7e8/w3" feat/s7e8-lecture-ui
   git worktree add "F:/001/wt-s7e8/w4" fix/s7e8-ui-consistency
   git worktree add "F:/001/wt-s7e8/w5" chore/s6-closeout
   git worktree add "F:/001/wt-s7e8/w6" docs/s7e8-integration
   ```
   每个 worktree 里要单独跑一次 `pnpm install`（pnpm 共享 store，不会重复下载）。
   **单窗口串行执行时跳过本步**，直接在主工作区按顺序 checkout 分支即可。
10. 广播：把**各自 worktree 的绝对路径**、契约文本路径、所有权矩阵、分文件编号告知六个窗口；窗口只在自己的 worktree 内改动，禁止跨目录写文件。

## 6. 验收标准

| 编号 | 标准 | 判定方式 |
| --- | --- | --- |
| G0-1 | P-1 / P-2 有书面结论并写入契约文本第 0 节 | 人工查阅，含日期与决策人 |
| G0-2 | 契约文本包含 §4 列出的全部七项，且 TS 签名可直接抄进代码 | 人工逐项勾选；W1 试写类型不报"字段未定义" |
| G0-3 | 行为表覆盖 11 种 URL 输入，每行有期望 `kind` 与 `watchUrl` | 数行数 = 11 |
| G0-4 | 六个分支名唯一且全部从同一基线 commit 创建 | `git rev-list` 比对基线 hash |
| G0-5 | 所有权矩阵与 14 号 §3 逐行一致，无文件被两个窗口认领 | 逐行核对 |
| G0-6 | 基线与分支信息写入报告，六个窗口均已收到契约路径 | 报告留痕 |

## 8. 本门禁特有风险

| 风险 | 缓解 |
| --- | --- |
| P-1 = 保留，但基线 tag 漏掉部分草稿，窗口基于不同基线 | 步骤 2 先 `git status` 核对再打 tag；G0-4 比对基线 hash |

| 冻结后私下改接口 | 契约变更单 + 广播 + 各窗口确认，禁止窗口间私下约定 |
| P-2 选 B 但矩阵没同步 | 选 B 时立即把 `router.ts`/`App.tsx`/`AppShell.tsx` 划归 W4 并写入契约文本 |
