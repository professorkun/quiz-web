## 1. 目标

清掉"待 S4/S5"这类与实际进度脱节的占位，让界面宣称的能力和真实能力一致，并补回归用例防止倒退。

## 2. 负责范围

| 类别 | 路径 |
| --- | --- |
| 白名单 | `apps/web/src/features/practice/**`、`features/me/ImportExport.tsx`、`apps/web/src/app.test.tsx`、features 下既有测试文件 |
| 可新建 | `web-v2/docs/reports/w4-parity-regression.md` |
| 黑名单 | `features/knowledge/**`、`BanksPage.tsx`、`styles.css`、`router.ts`、`App.tsx`、`ui/AppShell.tsx`、`cloud/**`、`core/**`、`content/**`、`项目规划/**`、所有 `package.json`、旧版根目录 |

**P-2 = A 的直接后果**：路由与外壳文件**冻结**，本窗口不碰；知识入口由 W3 在 `BanksPage` 内实现。
**共享文件处理**：`styles.css` 归 W3，本窗口只提需求清单；`app.test.tsx` 归本窗口，W3 的测试写在自己目录内。

## 4. 执行步骤

1. 全文搜索 `待 S4` / `待 S5` / `待 S6` / `待接入` 等占位文案，逐个判定：能力已存在 → 改为真实入口；确实不存在 → 改成明确的说明文案（不留"待"字）。
2. 「只刷未掌握」接 S4 状态机（用 `progress.status` 或既有 `onlyUnmastered` 引擎能力），保留禁用态仅当确实无数据。
3. 核对 `ImportExport.tsx` 的题库包预览：讲义信息展示（篇数/节数）与 W2 的产物一致；不改其数据解析逻辑（那是 W1 的范围）。
4. 在 `app.test.tsx` 补回归：六入口可进入且有实质内容、筛选与搜索、游客闭环（作答→错题→复习）不回退。
5. 若发现需要新增 CSS 类，整理成「样式需求清单」（类名 + 用途 + 期望表现）写进报告，**不直接改 `styles.css`**。
6. 跑 §6 命令，记录输出；按 §9 提交回执。
