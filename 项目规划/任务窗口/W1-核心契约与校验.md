## 1. 目标

让讲义新字段、视频 URL 解析、导入校验三件事在 `core/data` 落地，并能被 **Node 环境单测**证明；
同时保证旧题库包（含第二学科 chemistry、旧版迁移产物）零改动可读。

## 2. 负责范围

| 类别 | 路径 |
| --- | --- |
| 白名单 | `packages/core/src/**`（`schema.ts`、`validate.ts`、`index.ts`、`media.ts`、各 `*.test.ts`）、`packages/data/src/**`（`snapshot.ts` 及导入测试） |
| 可新建 | `web-v2/docs/reports/w1-contract-test.md` |

| 构建产物 | `*/dist/**` 本地可生成但**禁止提交**，由 INT 统一重建 |

报告目录只允许**新建** `w1-` 前缀文件，不改已有报告。

## 4. 执行步骤

1. 按契约扩展 `KnowledgeModuleSchema`：`goals` / `sections` / `videos` / `resources` / `estimatedMinutes` / `examFocus` 全部可选，`items` 由 `min(1)` 放宽为 `default([])`，`pitfalls` 保持 `default([])`。
2. 新增 `KnowledgeSectionSchema`（`title` + Markdown `body`）、`KnowledgeVideoSchema`（`url` + 可选 `title`/`note`/`startSec`）、`KnowledgeResourceSchema`；在 `core/src/index.ts` 导出全部 Schema、类型与解析函数。
3. 写 `media.ts`：纯函数 `parseMediaSource(raw, options?) → MediaSource`。**不得使用 `URL`**（core 的 tsconfig 不引 DOM/Node 类型），用正则取 query 参数与路径段。覆盖行为表 11 种输入；`javascript:` / `data:` / `vbscript:` / `file:` 判 `invalid` 并给可读 `reason`。
4. 写 `validateKnowledgeModules(input)`：数组检查 → 逐篇 Schema 校验（错误路径 `knowledge[i].字段`）→ 语义检查「`items` 与 `sections` 不得同时为空」→ 返回 `{ ok, issues, modules }`。
5. 在 `packages/data/src/snapshot.ts` 的 `parseBankJson` 接入：把原来的 `knowledge as BankContent["knowledge"]` 断言换成校验结果；任何问题都并入 `issues`，失败时 `value: null` 且不写入。
6. 补单测：
   - 契约：旧形态（仅 `items`）通过且新字段为空数组；新形态通过；视频缺 `url` 被拒；空讲义被拒且路径为 `knowledge[1]`；非数组直接报错。
   - 解析：行为表 11 种输入逐条断言；`b23.tv` 降级为 `page`；非法协议为 `invalid`。
   - 导入：畸形讲义包被拒、导入前后仓储无变化、导出→导入恒等。
7. 跑 §6 的全部命令，把输出贴进 `w1-contract-test.md`。
8. 按 §9 提交回执；**合并后立即执行 `pnpm -r build` 重建 dist 并通知 W2/W3**（这是串行依赖的兑现点）。
