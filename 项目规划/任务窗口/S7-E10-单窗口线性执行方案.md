## 1. 为什么改单窗口（模式变化带来的简化）

多窗口的分支矩阵、所有权矩阵、窗口看板，本质是为**并行防冲突**设计的。改成单窗口后，
这些机制可以退役，收益是：

| 多窗口机制 | 单窗口处置 | 理由 |
| --- | --- | --- |
| 六个窗口分支各自开发 | **一次性汇聚到 `integrate/s7-e8`**，之后只在这条线工作 | 无人争抢文件，分支隔离失去意义 |
| 所有权矩阵逐行约束 | 降级为「提交分组参考」 | 不再需要防同行冲突 |
| `window-board.md` 状态看板 | 不再更新 | 无并行窗口可跟踪 |
| 各窗口只认领自己文件 | 改为按**逻辑分组**提交 | 如「云相关」「包配置」 |
| 契约变更单流程 | 保留（契约仍是事实源） | 接口定义不因执行模式改变 |

**保留不变**：G0 冻结契约文本仍是唯一接口权威；GitHub 上传配置保护约束；`dist` 不提交；
P-2 路由冻结；视频可选扩展位口径。

---

## 2. 执行前须知（硬约束）

1. **上传配置不可动**：`origin`、`credential.helper=manager`、`.gitattributes`、
   `.github/workflows/**` 一律不改；不执行 `push --force`。
2. **精确 `git add <路径>`**，禁止 `git add -A` / `git add .`。
3. **`*/dist/**` 禁止提交**；CRLF 坑：讲义 `*.md` 生成前先 `sed -i 's/\r$//' *.md`。
4. **视频口径**：`videos: []` 是预期形态，不得重新塞回题库绑定链接，也不得删
   `KnowledgeVideoSchema` / `parseMediaSource` / `VideoCard` 等扩展入口。
5. **P-2 = A 仍有效**：`router.ts` / `App.tsx` / `AppShell.tsx` 冻结
   （`AppShell.tsx` 有草稿改动 → 按 §3 Step 5 处置）。
6. **不可逆操作**（T-8 真实迁移）需你提供凭据并在场，见 Step 7。

### Step 6 · 全量集成验证（对应 T-5，P1）
**目标**：出证据表，唯一最终判定。

**操作**：
```bash
cd F:/001/刷题/web-v2

pnpm --filter @quiz/core test
pnpm --filter @quiz/data test

# 重跑一次比对 sha256（幂等）
pnpm verify                          # 边界 + 扩展点 + 构建 + 空位对账 + 功能对等 + 单测
```
外加人工三项：断网文字讲义可读且零第三方请求、讲义→练习联动、数据持久化。
**注意** `pnpm verify` 可能复现 D-06（构建期清空 `dist/` 被安全策略拦截）——
处置方式是**改名不删源码**（`dist` → `dist.prev`），禁止 `rm -rf` 源码或清空 `build/`。

**验收**：全部命令退出 0；证据表（14 号 §6.3 模板）逐项无空缺。

**依赖**：Step 1~5 全部完成。
