## 1. 目标

把 7 篇讲义从"一句话要点"写成**零基础可精读**的 Markdown 源，并生成合规的 `knowledge.json`；
内容只改 Markdown、产物由脚本重建，延续仓库既有纪律。

## 4. 执行步骤

1. **先核对保留草稿**：`git status` 列出 `lectures/*.md`、生成脚本与 `knowledge.json`，确认 7 篇齐全后纳入版本管理；与 G0 契约比对 front matter 字段，有出入做最小修正并记录差异，**不重写正文**。随后完善 `lectures/README.md` 的格式说明、视频地址写法与质量门禁。
2. 逐篇复核（不足处补写）7 篇，对应 7 个 topicId：`web_base` / `jsp` / `servlet` / `spring` / `springmvc` / `mybatis` / `jdbc`。每篇固定八段：
   `学习目标 → 一分钟速览 → 分节正文（概念/流程/代码/对比表）→ 考试怎么考 → 自测清单 → 易错点 → 配套视频 → 拓展阅读`。
   正文用 Markdown 表格与围栏代码块；**代码块内不得出现以 `## ` 开头的行**（会被切节脚本误判）。
3. 写生成脚本：解析 front matter → 按 `## ` 切节 → 组装模块对象 → `JSON.stringify` 输出 `knowledge.json`。
   脚本内自带格式校验（必填字段、视频地址非空、节数、空讲义检查），**不 import `@quiz/core`**；校验失败退出码非 0 并指出文件名与行。
4. 写内容质量门禁单测：7 篇与 7 个 `topicId` 一一对应、每篇节数/字数/代码块/表格/目标/视频/易错点、小节标题不重复、所有视频 URL 可解析（本地按契约行为表校验，不依赖 W1 dist）。
5. 生成 `knowledge.json`，人工抽检 2 篇（技术准确性、代码可编译性、表格是否错位）。
6. 连续重跑两次生成脚本，比对字节一致；把统计写入 `w2-content-check.md`。
7. 按 §9 提交回执；合并后由 INT 用 W1 的 `validateKnowledgeModules` 复验一次。

## 6. 验收标准

| 编号 | 标准 | 判定方式 |
| --- | --- | --- |
| A-1 | 7 篇讲义与 7 个 `topicId` 一一对应，无重复 `moduleId` | 机器断言遍历 JSON |
| A-2 | 每篇 ≥8 节、≥3000 字、含 ``` 代码块与 Markdown 表格、≥3 目标、≥2 易错点 | 内容包单测逐篇 `it.each` |
| A-3 | 每篇有「这一节解决什么问题」「考试怎么考」「自测清单」三类小节 | 小节标题集合断言 |
| B-6 | 每条讲义至少 1 个可解析视频地址；全部条目通过解析器校验 | 内容包单测遍历 |
| W2-1 | 总正文 ≥50k 字 | 生成脚本统计输出 |
| W2-2 | 生成脚本重跑两次产物字节一致 | `md5sum` / `fc` 比对 |
| W2-3 | `knowledge.json` 通过 W1 的 `validateKnowledgeModules`（集成期） | INT 第 6 步复核 |
| W2-4 | 脚本不 import `@quiz/core`，可独立运行 | `node scripts/build-knowledge.mjs` 退出码 0 |
| W2-5 | 外链视频标注为"合集链接、请跳到对应章节"，无未验证的精确分集声明 | 人工抽查 7 条 |

## 8. 本窗口特有风险

| 风险 | 缓解 |
| --- | --- |
| 技术内容写错，误导学员 | 人工复核 + 对照唯一事实源 Markdown；单测只守结构不守正确性 | 
| 讲义体积拖慢首屏 | 集成时测 JS bundle 增量，超阈值（建议 ≤150 KB）由 W3 改按需加载 |
| 外链视频失效 / BV 号未验证 | W2-5 标注合集；文字讲义自足；季度巡检清单交 W6 写入维护说明 |

| 切节脚本把代码块里的 `##` 当标题 | 格式约定 + `lectures/README.md` 明示 + 生成时警告导语 |
