## 1. 目标

把契约变更、决策、职责表、状态与 changelog 全部留痕，避免"代码改了文档没跟"；
并把 P-1 / P-2 的决断同步到所有相关文档，让后续会话能独立看懂。

## 4. 执行步骤

**阶段 A（可并行起草）**

1. 把 P-1 / P-2 结论同步进 `13` 附录 C、`14` §0、以及 `任务窗口/` 各分文件的"已决前提"行（保持全文一致）。
2. 起草 ADR `0007-knowledge-lecture-schema.md`：新增字段全可选、`items` 放宽理由、旧数据零迁移、`schemaVersion` 是否升版及理由、外链视频"文字自足 + 可选 + 点击才加载"的约定。
3. 在 `00` §9 补变更登记行（讲义字段 / 外链视频 / 导入校验收紧 / 内容源改 Markdown 四项）；在 `08` §7 登记 S7-E8 事项卡。
4. 更新 `README.md` §2（讲义源与产物的关系、重建命令）与 `T0-7-文件职责表.md`（`lectures/` 可改、`knowledge.json` 禁止手改）。
5. 统一登记 npm script：根 `package.json` 与 `packages/content/package.json` 增加 `knowledge:build`（W2 只交脚本文件，不自行登记）。
6. 写 `CHANGELOG.md` 模板（按窗口分段，待回填）。

**阶段 B（串行收尾，须等 W1～W5 与 INT）**

7. 用 W5 的状态数据回填 `00` §8 阶段状态表（S6 改为通过、填验收日期与标签）。
8. 用 INT 证据表与各窗口报告写正式 changelog，**不留"以后补"**。
9. 打阶段标签（如 `general-v1.0.0` / `s7-e8-lectures`），核对 `00` §8 与 `w5-s6-closeout.md` 一致。
