## 1. 阶段目标

**目标陈述**：把"JavaWeb 题库 + 旧学习记录"从旧格式搬进一套**稳定、可校验、可重复生成、与平台无关**的数据契约里；此后所有页面、算法、同步都只认这套契约。

**为什么这一步必须在写页面前完成**：旧版用 `q.type + "-" + q.no` 作题目身份（如 `choice-1`），不同题库必然撞键；题目增删或重编号后，历史错题会指向错误的题。用户数据一旦按错的身份积累，越往后越不可挽救。

**可衡量目标**

| 编号 | 指标 | 目标值 | 验证方式 |
| --- | --- | --- | --- |
| G1-1 | 迁移完整度 | 147 题，分布 62/45/27/8/5 与旧版完全一致 | 迁移报告对账表 |
| G1-2 | 代码空位 | 89 个空位一个不丢，位置与解析可定位 | 逐题结构比对 |
| G1-3 | 旧记录可映射 | 旧 `q_key` 100% 有唯一新 ID，0 未映射、0 一对多 | dry-run 报告 |
| G1-4 | 幂等性 | 连续导入两次，输出内容与 ID 完全一致 | 两次输出 diff 为空 |
| G1-5 | 平台无关 | `packages/core` 单测在 Node 下全绿，零 React/Dexie/`wx.*`/DOM 依赖 | 单测 + import 静态扫描 |
| G1-6 | 失败可定位 | 任意非法导入报错含 `bankId` + `questionId` + 字段名 | 故障注入用例 |

## 2. 范围边界

**本阶段做**

- `web-v2/` pnpm workspace 骨架（`packages/core`、`packages/platform`、`packages/data`、`packages/content`、`apps/web` 空壳）
- 数据契约：Bank / Question / Attempt / Progress / Session / Topic / ExamTemplate
- Zod 校验层与 `schemaVersion`
- 可重复执行的旧 `data.json` → 新题库包适配器
- 知识点、讲义、模考规则从 JS 常量拆为内容配置
- 旧学习记录迁移的 **dry-run**（只出报告，不写云）
- `core` 单元测试

**本阶段不做**

- 不写任何可交互页面（`apps/web` 只到能启动的空壳）
- 不接 Dexie、不接云、不写 `localStorage`
- 不迁移生产云数据（只 dry-run）
- 不新增题型、不改题库内容（内容变更走 `content/javaweb-*` 到 `main`）
- 不移动根目录任何旧文件

**契约要点（必须逐条落在类型里）**

- 所有数据带 `schemaVersion`
- 题目用稳定 ID，不用数组下标或显示题号
- 学习记录引用 `bankId + questionId`
- 选项用稳定 `optionId`，A/B/C/D 只是展示序号
- 题目带 `revision`，`Attempt` 记录 `questionRevision`
- `Attempt` 不可变；掌握状态可重算
- 进度只存 ID 与结果，不重复存完整题对象
- 导入必须校验并给错误位置，禁止静默丢题

**题型联合类型（六种，本阶段定稿）**：`single_choice`、`multiple_choice`、`true_false`、`fill_blank`、`code_blank`、`short_answer`。新增题型只能通过"新增一个成员 + 渲染器 + 判分器"扩展，不得在页面里加 `if/else`。

## 6. 验收标准

### A. 数据完整性

- [ ] 新题库包题量 **147**，分布 **62 / 45 / 27 / 8 / 5**
- [ ] **89 个代码空位**数量一致，且每个空位可在题目结构中定位
- [ ] 每题 `topicIds` 均有对应 `Topic`，无悬空引用
- [ ] 所有 `bankId + questionId` 唯一；重复导入 ID 不变
- [ ] 每题有 `revision`，选项均有稳定 `optionId`
- [ ] 旧 `q_key` 与新 ID 一一对应，无一对多、无遗漏

### B. 契约与校验

- [ ] 缺答案、重复 ID、非法选项、空位缺失、未知字段，均**阻止导入**并报出具体位置
- [ ] 未知字段处理策略明确（拒绝或警告），不是静默丢弃
- [ ] `schemaVersion` 存在且迁移逻辑按版本分支
- [ ] 内容配置化：更换题库不改业务源码

### C. 工程

- [ ] `packages/core` 单测在 Node 全绿
- [ ] 静态扫描确认 `core` 未 import React / Dexie / `wx.*` / DOM API
- [ ] 旧版构建与冒烟仍全绿（未受影响）
- [ ] 迁移器连续执行两次，输出 diff 为空

### D. 关键场景（Given / When / Then）

1. **幂等导入**
   Given 已成功导入一次 JavaWeb 题库，When 不做任何修改再次执行迁移，Then 输出与首次逐字节一致，且所有 `questionId` 不变。
2. **旧内容更新可续接**
   Given `JavaWeb期末全题型题库.md` 在 `main` 上新增了 2 道题，When 在 `general-dev` 重新运行迁移器，Then 题库包变为 149 题，且新增题的 ID 不与已有题冲突，差异可审查。
3. **非法导入被拦住并定位**
   Given 某题 `answer` 字段缺失，When 执行导入，Then 导入失败并报出 `bankId=javaweb-final`、`questionId=choice-012`、字段 `answer`，且**没有写入任何部分数据**。
4. **旧记录映射**
   Given 旧数据中有 `choice-1` 的错题记录与掌握记录，When 执行 dry-run，Then 报告显示该记录映射到唯一新 ID，`Attempt` 保留原始答错事实，掌握状态由事件推导而非直接照抄"做对过"。
5. **平台无关**
   Given 一份 `core` 的判分函数，When 在 Node 环境运行测试，Then 无需任何浏览器 API 即可通过。

### E. 不可接受的情形

- 用"数组下标 + 显示题号"当 ID
- 迁移时"顺手修正"了若干题的答案或解析而未留差异记录
- 迁移脚本只能跑一次，或需要人工改中间 JSON
- `core` 里出现任何 React/Dexie/DOM 依赖（此错一旦进入，S8/S9 必然重写）
- 为了"看起来完整"而把 dry-run 直接写成真实写入

## 8. 阶段特有风险与应对

| 风险 | 触发信号 | 应对 |
| --- | --- | --- |

| dry-run 报告无人看 | 上云时才发现映射冲突 | 报告须有"冲突项与人工决策"小节，S6 前必须清零 |

## 9. 回退方案

1. **阶段内回退**：删除 `web-v2/` 或回退到阶段起点提交；旧版全程未被修改，用户无感。
2. **契约回退**：Schema 变更用 `schemaVersion` 升版 + 向上迁移函数，不覆盖旧版本数据。
3. **迁移器回退**：保留旧 `data.json` 作为唯一真源，任何时候可重新生成；不把新题库包当作不可再生资产。
4. **禁止**：在 `main` 上删除旧 `data.json` 或旧 HTML。
